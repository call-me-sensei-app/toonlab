# Reference-constrained C8 macro proof

Status: architecture proof only. The cliff-bedded r1 profile and sandstone-cliff
surface program have technical evidence, but neither has developer visual
approval. Do not fan this baseline out or describe it as final art.

## r5d cliff path

1. `cliff-bedded-grand-canyon-r1.json` binds the exact admitted nature image,
   generated six-view hypothesis, panel crops, derived foreground-mask hashes,
   pixel landmarks, axis maps, credit, licence, and rights text.
2. The evidence contract is deliberately
   `per-view-shape-normalized-authored-hypothesis`. The sheet is not a locked-
   scale photogrammetric capture and does not support an exact Grand Canyon
   reconstruction claim.
3. `referenceProfile.node.js` validates the template bytes and all polygons,
   then compiles correlated, bounded landmark variation once per seed and target
   dimension. Support landmarks are locked. Per-sample profile allocation or
   jitter is forbidden.
4. The macro envelope is the set intersection
   `max(frontXY, sideZY, topXZ)` in the deformed morphology frame, with a separate
   bottom-support constraint near the base. This max field is a sign/set field,
   not an exact Euclidean signed-distance field.
5. Sandstone surface program v8 keeps exactly one mesh-scale resistant package.
   It is finite laterally, asymmetric, and terminates at persistent joint gaps.
   Two narrow finite joint recesses, one edge-open block-loss step, and an
   asymmetric connected bedrock toe/apron modify the front-depth field. This is
   not loose talus; any separated talus blocks require supported geometry later.
   Thin bedding is excluded from macro geometry and emitted by
   `surfaceSemantics()` for baking.
6. `fieldContentId` binds the reference bytes/content ID, exact compiled macro,
   seed, target dimensions, recipe, and surface-program version. A changed
   profile, dimension, seed, or surface pass therefore creates new lineage.

The current deterministic visual checkpoint is generated from the median hero
seed at mesh resolution 64. The focused verifier covers evidence byte mutation,
semantic mutation, mask derivation, profile validation, deterministic compile,
linear scaling, projection containment, and topology. Visual recognizability
remains a separate fail-closed human gate.

## Existing C7 bake handoff

No new bake compiler is required for this macro proof. The minimum handoff is
already exercised by `scripts/verify-rock-geology-v2-basis-bakes.mjs`:

1. Compile C8 stages and retain `stages.basisField`.
2. Create the dense source with
   `createDenseDetailField(fixture.recipe, stages.basisField, options)`. This
   consumes `surfaceSemantics()`, so thin sandstone bedding reaches neutral base
   colour and the shared dense field without becoming repeated macro shelves.
3. Call `compileRockBakeV2(..., { productionField: stages.basisField,
   fieldContentId: stages.basisField.descriptor.fieldContentId,
   fieldKind: 'c8-basis-field-v2', detailField, bounds })`.
4. The existing compiler produces the dense source, UV render mesh, fallback
   meshes, collision, tangent normal, signed height, AO/roughness, cavity,
   material/fabric, fracture, and weathering pages from that shared field.

This hook should only be run for the single exemplar after macro visual approval.
It is not permission to launch the all-family bake or qualification matrix.

## Production ownership boundary

The basis implementation is a bounded experiment. Production profiles belong
in each canonical editable-source package as reviewed `visual-hull` primitives;
tower-like sources require a corresponded-polygon loft and arches require an
explicit subtractor/support graph. The basis switch must not become a registry
of roughly one thousand baselines. A seed variation is a derivative of one
reviewed baseline, not a new baseline.
